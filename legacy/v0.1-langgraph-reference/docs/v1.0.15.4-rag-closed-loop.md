## 跨项目教训 (重要)

### 1. server 端 dev 落后 master 79 commits — 隐藏 deploy bug

**症状**: 我 push 完 master, server 端 deploy 完 mavis 启动, 但 server 端 git log 显示还在 `1d213a4` (v1.0.15.2), 不是我刚 push 的 `4768864` (v1.0.15.4)
**根因**: server 端 default branch = dev, 我本地 push 只 push master
**真相**: 之前 v1.0.15 / v1.0.15.1 / v1.0.15.2 / v1.0.15.3 是不是都白 deploy? 让我看

**治本** (跨项目):
- 任何多分支项目 deploy 必含 "post-deploy sanity check" 跑 1 个 e2e test, 验 deliverable 长度 > 0
- 不能只信 "git pull ok + curl /health 200" — server 端可能还跑老 code
- 加 cron 监控 `git log --oneline -1` vs `git log --oneline origin/master -1`, 不匹配 → 报警

### 2. "看似成功 = 假成功" 治本 (跨项目)
- 跑 1 个简单 wf, 验 "save_kb_entry 调通" + "deliverable 长度 > 0" + "task duration > 1s"
- 不能只信 "wf finished=True" — 可能没真调
- 跨项目: 任何 e2e test 必含 "assert tool_call counts > 0" + "assert output length > N"

### 3. agent 反复追问能力治本 (v1.0.15.3 + v1.0.15.4 跨项目)
- 不能只改 prompt (LLM 飘忽)
- 必须 server 端兜底: tool dispatch 后检查必备 tool 是否调过
- 兜底分两阶段:
  * 跑中 (5 iter 兜底): 跑 N 轮还没调 X → 强制 error
  * finish 阶段 (v1.0.15.4 治本): 准备 finish 但还没调 X → 强制续跑 1 轮, reminder 提示
- minimax 1 iter final_content, 跑中兜底来不及, finish 阶段兜底才是真治本

### 4. push master → dev sync 关系 (跨项目)
- 多分支项目: master 是 production, dev 是 dev, deploy 端用 dev 还是 master 要明确
- push master 必同时 push master:dev (或 master:deploy) 保持同步
- 或: deploy 直接 fetch master (不 fetch dev)
