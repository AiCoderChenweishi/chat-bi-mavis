### 2. LangGraph 启用 (真智能体编排 state machine)

**架构**:
```
START → plan → dispatch_worker → run_worker → check_status → (loop | mark_done) → END
```

**State** (LangGraph TypedDict):
```python
class ManagerState(TypedDict, total=False):
    tasks: List[Dict]              # task list
    log: List[Dict]                # manager log
    iteration: int                 # 循环次数
    is_done: bool
    final_deliverable: Optional[Dict]
    form: Dict
    pending_question: Optional[str]
    plan_recommended_count: int
    total_placeholders: int
```

**节点**:
- `dispatch` (派 ready task 标 running)
- `run_worker` (调 agent_runner.run_agent + 写回 result/output/report)
- `mark_done` (拼 final_deliverable)

**API**:
- `run_manager_langgraph(initial_plan, form, user_question_callback, workflow_id, max_iterations, on_log, on_board_update)`
- server.py 优先用 LangGraph, fallback 老 manager_agent

**踩坑**:
- **langgraph 1.2.9 装到 server 端 .venv (python 3.14) 没 cache/ 目录**: 装 `langgraph<0.5` (0.4.10) 才有 cache
- **langchain-core 1.5.1 依赖链断**: 需要 sniffio / distro / packaging / requests / urllib3 / chardet / uuid_utils / jsonpatch / langsmith 等 8+ no-deps 包
- **task id**: 用 plan id (s1/s2) 不要 hash 重新生成, 否则 depends_on 不匹配
- **astream** 末尾手动 merge new_state 到 final_state (LangGraph 不 mutate state in place)

### 3. agent_runner run_agent 缩进 bug 治本

**根因** (从 v1.0.13 之前就有, 一直没人发现):
- 2 个 return 缩进错, 永远跑, 跳过后续代码:
  1. line 122: except 块后 `return result` 8 空格 (跟 try/except 同级) — try 走完就跑 (final_content 还没设 → 空), 后续 content=resp.get(...) 是死代码
  2. line 142: if not tool_calls 块后 `return result` 8 空格 (跟 if 同级) — 走完 if 也跑, tool 处理死代码
- 修: 改 2 个 return 缩进到 12 空格 (在 except 块 / if 块内)

**为什么之前没人发现**:
- minimax LLM 行为: 1.6s 跑完, placeholder_count=0 (因为 final_content 空 → _finalize_scan 跳过)
- "8/8 done 0 placeholder" 看起来成功, 实际 deliverable 全空
- 现在 minimax 跑 4-12s/step, 出来 500 字符真内容 (4-6 节报告 + TASK_DONE)

## 跨项目教训 (新增)

### 1. 缩进 + return 位置 = 死代码 bug
任何 Python 函数 if/except/try 块后的 return 缩进错, 永远跑, 跳过后续代码. 修法: 2 个 return 缩进到 12 空格 (在块内).

### 2. server.py return format 对齐
老代码返 TaskBoard 对象 + .summary() 方法, 新代码返 dict + .get('board_summary'). server 端要兼容两种 — 用 hasattr 判断.

### 3. LangGraph 装依赖链
python 3.14 + langgraph 1.2.9 兼容性问题 (没 cache/). 装 0.x 稳定版 + 手动装 8+ no-deps 包 (sniffio, distro, packaging 等).

### 4. 看似成功 = 假成功
"8/8 done 0 placeholder" 看起来成功, 实际 deliverable 全空. placeholder_count=0 不能代表内容好, 要看 final_content 长度. minimax 行为 (1.6s 跑完) 掩盖了真 bug.
